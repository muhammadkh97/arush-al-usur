# خطة تنفيذ النموذج العمودي (Phase 1) — Unity

خطة بناء عملية لـ Vertical Slice فقط. النطاق الملزم: `vertical-slice-scope.md`. القرارات المقفلة: `project-context.md`.

| الحقل | القيمة |
|---|---|
| المرحلة | Phase 1 — Vertical Slice |
| المحرك | **Unity** (iOS/Android) |
| هدف أول بناء قابل للّعب | حلقة: تسجيل → فصيل+بطل → قصر≤5 → تدريب → غارة NPC → تقرير → تحالف+مساعدة |
| خارج هذه الخطة | مواسم، عروش، قلعة تحالف، متجر مدفوع، فرسان/حصار، Battle Pass |

---

## 1. مبادئ التنفيذ

1. **عميل Unity + خلفية تطوير واحدة** في البداية (monolith dev API مقبول).
2. كل منطق قتال/نهب/إنتاج **مصدر الحقيقة فيه السيرفر**؛ العميل يعرض ويطلب.
3. العربية RTL من أول مشهد واجهة — مفاتيح ترجمة من اليوم الأول حتى لو المحتوى عربي فقط.
4. الفصيل يُكتب مرة عند الإنشاء في سجل الحساب — **لا API لتغيير الفصيل**.
5. لا تُبنى هياكل متجر/موسم/قلعة «للمستقبل» داخل الشريحة إلا كواجهات فارغة ممنوعة من الدمج.

## 3. المشاهد والوحدات (Scenes / Modules)

| المشهد | المسؤولية | وحدات Scripts أساسية |
|---|---|---|
| `Boot` | تحميل إعدادات، خدمات Net، i18n، Analytics | `AppBoot`, `ServiceRegistry`, `LocaleRtlBootstrap` |
| `MainMenu` | دخول ضيف / جلسة | `AuthController` |
| `CharacterCreate` | اختيار فصيل + عرض البطل؛ إنشاء مدينة | `FactionSelectUI`, `HeroPreview`, `CreateCityRequest` |
| `City` | بناء/ترقية، طابور، إنتاج مرئي، HUD، بطل، مهام، تحالف (نوافذ) | `CityGrid`, `BuildingActions`, `BuildQueueView`, `ResourceBar`, `HeroPanel`, `AlliancePanel`, `QuestPanel` |
| `WorldMap` | قطاع 50×50، NPC، جمع برّي، إرسال مسيرة | `MapGrid`, `MarchCommander`, `NpcMarker`, `StaminaView` |
| (Overlay) تقرير القتال | نتيجة عربية | `BattleReportUI` |
| `DevSandbox` | تسريع زمن السيرفر، منح موارد | `DevCheats` (يُستبعد من بيلد الاختبار الرسمي) |

### وحدات منطقية (وليس مشاهد)
| الوحدة | Must-have Phase 1 | ملاحظة |
|---|---|---|
| Auth | ضيف بجهاز + token جلسة | ترقية حساب = هيكل فقط |
| City / Buildings | مباني الجدول في النطاق حتى الحدود | قصر أقصى 5 |
| Economy | تكة إنتاج + مستودع حماية ≤5 | جداول من `economy-combat-tables.md` |
| Army / Train | مشاة، رماة، خاصة فصيل L1 | بلا فرسان/حصار |
| March | جمع، غارة NPC | زمن حقيقي قصير؛ ×2/×5 في dev |
| Combat Report | فوز/خسارة/نهب/جرحى | السيرفر يحسب؛ سقف بطل 25% |
| Hero | بطل واحد، مهارة+سلبية، تجهيز×2 | أسماء GDD كما هي |
| Alliance | إنشاء/انضمام/مغادرة/مساعدة بناء | **بلا قلعة** |
| Analytics | الأحداث الأساسية الستة+ | بلا متجر |

## 4. جداول البيانات (Data Tables) — Phase 1 فقط

تُوضع في `data/` وتُحمَّل على السيرفر؛ العميل يستلم عبر API أو ScriptableObjects مولَّدة.

| الملف | المحتوى |
|---|---|
| `factions.json` | المعرّفات الثلاثة، بونصات ظاهرة، وحدة خاصة، `starterHeroId`؛ علم `factionChangeAllowed: false` |
| `heroes_launch.json` | أسد الرمال / قائد الفيلق الذهبي / فارس النوروز — أرقام §7.4 من جداول القتال |
| `buildings_l1-5.json` | تكاليف/أزمنة/إنتاج للمستويات 1–5 للمباني داخل النطاق |
| `units_slice.json` | مشاة خفيفة، رماة، مهندسو المنجنيق، فيلق مدرّع، رماة مركّبة — L1 فقط |
| `warehouse_protection.json` | حماية مستودع L1 و L5 |
| `stamina.json` | سقف 120، تجدد، تكاليف جمع/غارة |
| `combat_constants_slice.json` | مضاد مشاة/رماة فقط + معاملات مبسّطة + سقف بطل 0.25 |
| `npc_camps.json` | ≥20 معسكر بمستويات قوة للغارة التعليمية |
| `quests_daily_slice.json` | 3–5 مهام تمنح موارد/تسريع دقائق |
| `alliance_slice.json` | سقف أعضاء 30؛ معاملات مساعدة البناء |

**لا تُدرَج** جداول عروش، Season Pass تسعير، فرسان، حصار، قلعة — حتى لا تُستهلك بالخطأ.

## 5. الخلفية: Stub مقابل حد أدنى حقيقي

| القدرة | Stub مقبول؟ | الحد الأدنى الحقيقي المطلوب لنجاح الشريحة |
|---|---|---|
| تسجيل ضيف + JWT/session | — | **حقيقي** على سيرفر تطوير |
| إنشاء مدينة + اختيار فصيل (مرة) | — | **حقيقي**؛ رفض أي `changeFaction` |
| حالة مدينة ومبانٍ وطابور | عميل-فقط مرفوض للنجاح | **حقيقي** مع استمرارية بعد إعادة الفتح (T7) |
| تكة إنتاج الموارد | يمكن تسريعها | **حقيقي** على السيرفر (ولو كل 60ث) |
| تدريب وحدات | — | **حقيقي** |
| مسيرة + timestamp وصول | محاكاة محلية مرفوضة للنجاح | **حقيقي**؛ worker/tick يصلّح عند الوصول |
| حل قتال NPC | صيغ ثابتة محلية مرفوضة | **حقيقي** وفق مخطط الحل المبسّط |
| تقرير قتال مخزَّن | — | **حقيقي** يُجلب بعد العودة |
| تحالف + مساعدة | ذاكرة فقط في عملية واحدة مرفوضة إن كسرت T4 بين جهازين | **حقيقي** لحسابين على نفس السيرفر |
| Push إشعارات | **Stub / داخل الجلسة** | اختياري |
| IAP / متجر | **لا تُبنَى** | — |
| موسم / عروش / قلعة | **لا تُبنَى** | — |
| دردشة | **Stub أو حذف** | ليست must-have |
| مطابقة سيرفرات متعددة | **Stub** سيرفر واحد | — |

### عقود API أولية (أسماء توجيهية)

```
POST /v1/auth/guest
POST /v1/city/create          { factionId }   # يرفض إن وُجدت مدينة
GET  /v1/city/state
POST /v1/city/build           { buildingType, tileId? }
POST /v1/city/train           { unitId, count }
GET  /v1/map/sector
POST /v1/march/start          { type, targetId, army, heroSkillChoice? }
GET  /v1/march/{id}
GET  /v1/reports/{id}
POST /v1/alliance/create|join|leave
POST /v1/alliance/help        { targetPlayerId, timerId }
GET  /v1/hero
POST /v1/hero/upgrade-skill|{level}
POST /v1/analytics/event
```

بيئة تطوير: علم `timeScale` = 1 | 2 | 5 لتسريع المسير/البناء في الاختبار دون تغيير الجداول.

## 6. معالم التسليم الداخلية (Milestones) — Phase 1 فقط

### M0 — تأسيس المشروع
- [ ] إنشاء مشروع Unity + هيكل `_Project` أعلاه
- [ ] مشهد Boot + i18n عربي RTL على شاشة واحدة
- [ ] سيرفر تطوير فارغ بصحة `GET /health`
- [ ] مجلد `data/` بأول مسودة JSON من الجداول 1–5

**خروج:** تطبيق يفتح على جهاز/محاكٍ ويعرض قائمة عربية.

### M1 — Slice-A: مدينة واقتصاد
- [ ] CharacterCreate: ثلاثة فصائل + بطل؛ قفل الفصيل في DB
- [ ] مدينة: بلاطات مباني النطاق؛ طابور بناء واحد؛ قصر→5
- [ ] إنتاج الموارد الأربعة + شريط موارد
- [ ] مستودع حماية حسب الجدول

**خروج:** لاعب اختبار يرفع قصراً إلى 5 ويشاهد مخزوناً يزداد.

### M2 — Slice-B: جيش ومسيرة وتقرير
- [ ] ثكنات + ميدان رماة + وحدة خاصة للفصيل
- [ ] خريطة قطاع + ≥20 NPC
- [ ] مسيرة جمع وغارة؛ طاقة مسير
- [ ] تقرير قتال عربي؛ مستشفى جرحى

**خروج:** T2 و T3 و T6 تمر؛ زمن أول مسيرة ناجحة يُقاس (<12 د هدف).

### M3 — Slice-C: بطل وتحالف
- [ ] لوحة بطل: مستوى، مهارة، سلبية، تجهيز×2
- [ ] سقف مساهمة 25% ظاهر في أدوات dev للتقرير
- [ ] تحالف: إنشاء/انضمام؛ زعيم+عضو؛ مساعدة بناء
- [ ] قائمة أعضاء وقوة تقريبية

**خروج:** T4 و T5 تمر على حسابين.

### M4 — Slice-D: صقل وقبول
- [ ] Onboarding ≤6 خطوات؛ مهام يومية 3–5
- [ ] أحداث Analytics الأساسية
- [ ] إصلاح RTL على كل شاشات النطاق
- [ ] تمرير T1–T7 على جهاز حقيقي بلا blockers
- [ ] إزالة/تعطيل DevSandbox من بيلد القبول

**خروج:** **Vertical Slice مقبول** → يُفتح التخطيط لـ Phase 2 (بما فيه قلعة التحالف).

## 7. معيار «أول بناء قابل للّعب» (First Playable)

يُعلن First Playable عند اكتمال **M2 كحد أدنى** على Android (أو محاكٍ معتمد) بحيث:

1. حساب جديد يختار فصيلاً ويحصل على البطل.
2. يبني حتى يظهر تقدم قصر (≥3 عملياً؛ هدف القبول النهائي 5).
3. يدرّب ≥50 وحدة ويرسل غارة NPC ويستلم تقريراً عربياً.
4. الحالة تبقى بعد قتل التطبيق وإعادة الدخول.

القبول النهائي للمرحلة = M4 + T1–T7، وليس First Playable وحده.
