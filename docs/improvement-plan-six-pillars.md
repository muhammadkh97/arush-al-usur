## 0. ملخص تنفيذي

الشريحة الحالية تُثبت الحلقة الأساسية (بناء → تدريب → مسير → تقرير → تحالف → بطل)، لكن الركائز الست ما زالت **هيكلًا مبسّطًا** بصريًا ووظيفيًا: مباني SVG ايزومترية مسطّحة نسبيًا، وحدات بلا نماذج، قلاع خارجية شبه أيقونات، أبطال بمهارتين، حقول بـ `yieldHint`، ووحوش بحاميات مجردة.

**أهم قرار جودة في هذه الخطة: التركيز على 3D.**  
شريط القبول البصري لكل الركائز الست هو **عرض ايزومتري حقيقي 2.5D–3D** (عمق، إضاءة ساعة ذهبية، ظلال، نماذج/شبكات مبسّطة)، لا تحسين رسوم SVG مسطّحة وحدها.

| الطبقة | التقنية | الدور |
|---|---|---|
| نموذج متصفح (صقل) | **Three.js + WebGL** (مشهد قلعة + معاينة عالم) | إثبات المظهر والتفاعل قبل Unity؛ HUD يبقى HTML/CSS RTL |
| إنتاج موبايل | **Unity 3D** (URP مفضّل) | العميل النهائي؛ نفس كاميرا ايزومترية ومبادئ إضاءة/LOD |
| بيانات مشتركة | `data/*.json` | أنظمة اللعب لا تتغير بالمحرّك |

مرجع المظهر: `preferences.md` + `media/refs/target-castle-quality.jpg` — فن أصلي فقط، بلا IP منافس.

### 0.1 عقد الجودة 3D (ينطبق على كل ركيزة)

| البند | المتطلب |
|---|---|
| الكاميرا | ايزومترية ثابتة الميل (≈35–45°) مع دوران/تكبير محدود في المعاينة |
| الإضاءة | **ساعة ذهبية**: شمس دافئة منخفضة + إضاءة تعبئة باردة خفيفة + هيميسفير |
| الظلال | ظل اتجاهي ناعم على الأرض والمباني (Intensity معتدلة على الموبايل) |
| المواد | PBR مبسّط (albedo + rough) أو توسترد؛ قبب/معدن HUD متناسق |
| LOD | LOD0 قريب (قلعة/بطل)، LOD1 عالم، LOD2 أيقونة بعيدة — انظر جداول الركائز |
| الأداء هدف معاينة | ≥30 fps على جهاز متوسط عند مشهد القلعة الكامل |
| مرفوض كهدف نهائي | الاكتفاء بـ SVG مسطّح أو سبرايت 2D بلا عمق/ظل كـ «جودة مكتملة» |

> SVG الحالي مقبول **كمرحلة انتقالية / fallback** فقط حتى يُستبدل مشهد Three.js؛ كل معلم (M-A…M-F) يشترط **ترقية 3D مرئية** في لقطة قبول.

### ترتيب التنفيذ المقترح (أولوية المستخدم + اعتماديات + 3D)

### 1.3 فن/تقنية 3D — المباني

| البند | المواصفة |
|---|---|
| المظهر المستهدف | مدينة مملكة موبايل ايزومترية؛ قصر ذو قبة مزخرفة في المركز؛ ساعة ذهبية؛ رمال/خضرة حسب الفصيل |
| معاينة متصفح | Three.js: أرضية + مباني كـ Box/Extrude أو GLB خفيف لكل نوع؛ اختيار مبنى بالـ raycast |
| إنتاج Unity | نفس التخطيط من `castleInteriorLayout`؛ Prefabs URP؛ إضاءة Directional + baked/realtime shadow حسب الميزانية |
| LOD | LOD0: المبنى المحدّد + الجيران القريبون بتفاصيل؛ LOD1: بقية المدينة مبسّطة؛ خارج الإطار لا تُرسم |
| إضاءة/ظلال | شمس ذهبية (~40°)، ظل ناعم، انعكاس خفيف على القبة فقط |
| انتقال من SVG | الإبقاء على SVG كـ fallback إن فشل WebGL؛ هدف القبول = مسار WebGL |

### 1.4 معايير القبول — المباني

- [ ] وظائف + ≥1 مهمة «استخدم» لـ: مزرعة، ثكنة، مستشفى، سفارة، ضريح.
- [ ] **مشهد قلعة 3D** يظهر عمقًا وظلًا وإضاءة ساعة ذهبية (لقطة قبول).
- [ ] القصر يقرأ كعنصر بطولي بصريًا (لا يطغى عليه HUD).
- [ ] ≥30 fps معاينة على جهاز متوسط؛ لمس اختيار مبنى ≥44px عبر proxy HTML إن لزم.

| تنين الصحراء | 3 | ~2 200 | **≥ 3 000** | موارد كبرى + رمز أسطوري |

معدّلات خاصة خفيفة كما في التصميم السابق (باف جمع، تضاريس أثر، جرحى أعلى عند الفشل).

### 6.3 فن/تقنية 3D — الوحوش

| البند | المواصفة |
|---|---|
| المظهر | قراءة فورية للحجم: قوافل صغير، جني متوسط، شبح طويل شفافية، تنين الأكبر ظلًا |
| معاينة متصفح | GLB مبسّط أو شكل منحوت؛ idle loop؛ توهج طفيف مقبول فقط للتنين/الشبح دون «glow UI» مفرط |
| Unity | نفس الأصول مع LOD؛ VFX مهارة عند التقرير لاحقًا |
| LOD | LOD0 عند التركيز؛ LOD1 ظل+شكل؛ LOD2 أيقونة وحش على الزوم البعيد |
| إضاءة | Rim بارد للشبح؛ دافئ للتنين؛ لا كسر الحساسية الثقافية (أسطورة أدبية) |
| UX | القوة الموصى بها نصًا على البطاقة **وفوق** النموذج |

## 7. الاعتماديات بين الركائز

```
المباني (مشهد 3D أساسي)
   ├──► الجيش (معاينة وحدات في/عند المباني)
   ├──► الأبطال (الضريح + شاشة 3D)
   └──► الحقول (حاجة اقتصاد → عقد عالم 3D)

الجيش ──► الحقول / الوحوش / غارة القلاع (أرقام قوة)
الحقول + قلاع 3D ──► تماسك خريطة العالم
الأبطال ──► باف داخل سقف 25٪ على الجيش/الوحوش
الوحوش ──► تحتاج خريطة 3D + جداول جيش جاهزة
```

| تأخير… | الأثر |
|---|---|
| مباني بلا 3D | يفشل شريط الجودة الأساسي للمشروع |
| جيش بلا نماذج | تبقى الأرقام صحيحة لكن الحضور ضعيف |
| عالم SVG فقط | مرفوض كقبول نهائي لركيزة القلاع/الحقول/الوحوش |
| أبطال/وحوش متأخرة | لا تعيق مدينة 3D؛ تُغلق السلسلة لاحقًا |

## 8. المعالم التنفيذية (Three.js ثم Unity)

**قاعدة صارمة:** كل معلم M-* يُرفض إن لم تتضمّن لقطة القبول **ترقية 3D مرئية** (عمق + إضاءة ساعة ذهبية + ظل حيث ينطبق). تحسين SVG وحده لا يُغلق المعلم.

### 8.1 صقل المتصفح

| معلم | أنظمة اللعب | ترقية 3D الإلزامية | مخرجات |
|---|---|---|---|
| **M-A** | وظائف/مهام مباني | مشهد قلعة Three.js + ظل + قبة بطولية | لقطة قلعة 3D؛ quests مبانٍ |
| **M-B** | وحدات L1–L2 + فتح | معاينة وحدة 3D × فئات الشريحة | `units_slice` محدّث؛ لقطة تدريب |
| **M-C** | حقول بمستوى/مخزون | بلاطات موارد 3D على العالم | `resource_fields.json`؛ تقرير جمع |
| **M-D** | شارات قلاع + بطاقة موحّدة | قلاع عالم mesh/LOD ليست دوائر SVG | لقطة عالم 3D |
| **M-E** | بطاقة بطل/دور/T5 | نموذج بطل 3D في الشاشة | لقطة بطل |
| **M-F** | قوة موصى + مكافآت | نماذج وحوش 3D مميزة | `monsters.json`؛ لقطة وحش |

الترتيب: **M-A → M-B → M-C → M-D → M-E → M-F**.

مسار تقني مقترح للمتصفح:

1. إدخال Three.js لمشهد «داخل القلعة» مع الإبقاء على HUD HTML RTL.
2. مشاركة Rig الإضاءة (ساعة ذهبية) مع مشهد العالم.
3. تحميل GLB/أصول من مجلد `prototype/assets/3d/` (يُنشأ عند التنفيذ).
4. Fallback SVG إن `WebGLRenderingContext` غير متاح — مع شارة «وضع مبسّط»؛ القبول الرسمي على WebGL.

### 8.2 ترحيل Unity (الإنتاج)

| معلم | المحتوى |
|---|---|
| **U1** | مشروع URP؛ استيراد بيانات؛ مدينة 3D وفق M-A (Prefabs لا SVG) |
| **U2** | وحدات + قتال تقرير؛ نماذج وحدات وفق M-B |
| **U3** | خريطة استراتيجية 3D: قلاع/حقول/وحوش (M-C/D/F) |
| **U4** | أبطال 3D + سقف 25٪ سيرفر؛ تحالف أساسي |
| **U5** | Soft: إسطبل، حصار، قلعة تحالف، سوق — مع نفس شريط جودة 3D |

### 8.3 خارج صقل الشريحة

قصر >5، فرسان/حصار كاملة، قلعة تحالف، مواسم/عروش، متجر مدفوع، PvP حقول، ظهورات سيرفر كاملة — مع الإبقاء على **مسار الأصول 3D** جاهزًا لعدم إعادة العمل الفني.
